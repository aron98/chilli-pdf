# What is preserved during conversion

User-facing summary of how chilli-pdf treats the parts of your document
that are not the scanned page images, what is verified to survive a
conversion, and where the limits are. The verification status of every
claim here is tracked in `docs/verification-plan.md`.

## How the conversion works

chilli-pdf appends an invisible text layer (render mode `3 Tr`) to each
page's existing content streams and never re-renders or rewrites the
original page content. The output is written as a new file; **the input
file is never modified**. Everything else in the document — the page
tree, metadata, bookmarks, links, images — is carried over as-is
because it is simply never touched.

## Verified to survive a conversion

All of the following are exercised end to end by the automated tests in
`tests/preservation.rs` (see also the appearance checks in
`tests/overlay.rs`):

- **Page count, order, dimensions, and rotation.** Page objects keep
  their original object ids and `/Kids` order; `/MediaBox`, `/CropBox`,
  and `/Rotate` are unchanged, including 90°-rotated pages
  (`page_tree_and_order_are_unchanged_for_every_fixture`,
  `rotated_page_with_metadata_survives_the_overlay`).
- **Document metadata.** The trailer's `/Info` dictionary survives as
  the same object with every entry unchanged: `Title`, `Author`,
  `Subject`, `Keywords`, `CreationDate`, `ModDate`, custom
  (XMP-style) keys, and non-Latin values (Unicode `ő`, `ű` are covered
  by fixtures with UTF-16BE titles). Metadata is carried over
  untouched — it is never reset, and `ModDate` is deliberately **not**
  bumped, because the document's nominal content did not change; only
  searchability was added
  (`info_dict_entries_survive_the_overlay`,
  `rotated_page_with_metadata_survives_the_overlay`).
- **Bookmarks / outline.** The full outline tree survives with all
  nesting levels, titles, and destinations (both `/Dest` arrays and
  `/A` GoTo actions), still pointing at the original page objects
  (`outline_titles_and_destinations_survive_the_overlay`).
- **Links.** Internal links (direct `/Dest` and `/A` GoTo actions) and
  external URI links keep their annotations, hit rectangles, and
  targets. The overlay adds no annotations and does not touch
  existing ones, so link hit areas are unaffected
  (`internal_and_external_links_survive_the_overlay`).
- **Existing page resources.** Fonts and other resources already on a
  page are kept; the OCR font is added alongside them under the name
  `ChilliOcrF1` (`existing_font_resources_are_kept_beside_the_overlay_font`).
- **The input file itself.** Every test asserts the input file is
  byte-identical after a conversion.

## Deliberate, semantics-preserving changes

The output file is a PDF that renders identically, but a few internal
structures are normalized on the way through:

- A page's `/Contents` becomes an **array** of streams (original
  stream(s) first, the invisible text overlay appended last) whenever
  it was a single stream before.
- Inline `/Resources` dictionaries — and inline `/Resources /Font`
  dictionaries — are moved into indirect objects so the overlay font
  resource can be attached. This is a structural change only; the
  resource semantics and every existing entry are preserved.
- The output is written with a classic cross-reference table. Inputs
  using cross-reference or object streams are re-expanded into the
  classic layout. This affects tooling that inspects the xref style,
  not the document's meaning.

## Limits

- **Encrypted documents** are refused up front; they must be decrypted
  by the user first. **Digitally signed** documents are also rejected,
  because any edit invalidates the signature.
- **Damaged cross-reference data** is not silently repaired: if the
  input's xref cannot be read as-is (lopdf would have to reconstruct it
  from raw bytes), the conversion fails with an unreadable-file error
  instead of editing objects through a guessed table.
- The committed test corpus covers classic-xref PDF 1.4 inputs
  (regenerable fixtures under `tests/fixtures/preservation/`). Xref-stream
  and object-stream inputs are accepted but get re-expanded to the
  classic layout by the writer; that path is not covered by the
  committed preservation tests.
- If a page already contains invisible OCR text from another tool, the
  added layer is appended on top of it; removal of a previous layer is
  out of scope for version one.

## Test fixtures

`tests/fixtures/preservation/` contains four small committed PDFs
generated by `make_fixtures.py` (no binary blobs by hand): one with a
Unicode Info dictionary and shared font resources, one with a
three-level outline, one with internal and external links, and one
90°-rotated page with metadata. Each fixture passes `qpdf --check`
and is reloaded and compared object by object in the tests above.
